# 用户笔记制卡引导规则（路径 C）

当输入来源是用户自己的笔记（每日记录、回顾思考、inbox 整理等）时，遵循本规则。

核心理念：用户的零散记录中蕴含值得长期保留的想法，帮用户识别、提炼、沉淀为永久笔记。

---

## 阶段一：内容扫描与观点识别

### 扫描策略

1. 通读用户提供的笔记内容
2. 识别其中可独立成卡的观点、想法、发现
3. 区分"事实记录"和"有观点的思考"——只有后者值得制卡
4. 编号列出候选观点

### 候选展示格式

```
从你的记录中，我识别出以下值得沉淀的想法：

1. **{{观点概括}}** — 来自：{{记录中的具体内容}}
2. **{{观点概括}}** — 来自：{{记录中的具体内容}}
3. **{{观点概括}}** — 来自：{{记录中的具体内容}}

你想把哪些做成永久笔记？也可以告诉我遗漏了哪些。
```

### 识别要点

- 用户的感悟、反思、经验总结 → 好的候选
- 纯事实记录（今天做了什么） → 通常不适合制卡，除非用户有特殊想法
- 情绪表达如果背后有洞察 → 可以制卡（引导用户提炼出洞察）
- 碎片想法如果相互关联 → 可合并为一个候选

---

## 阶段二：逐条深度判定与补充

对用户选择的每条候选，进入深度充足性闸门（见 SKILL.md 共享规则）。

### 用户笔记场景的特殊性

- 用户笔记的观点是用户自己的，不存在"用别人观点代替自己思考"的问题
- 但常见的不足是：观点明确但缺少"为什么"和"边界条件"
- 关键引导方向：
  - "你为什么这么觉得？有什么经历让你这么想？"
  - "这个想法在什么情况下会失效？"
  - "能举一个具体的例子吗？"

### 与其他路径的区别

- 不需要"思考方向推荐"（用户已有想法）
- 不需要从洞见条目中提取（内容就是用户原话）
- 引导重点是帮用户把"感觉对"变成"说得清楚"

---

## 阶段三：逐张制卡

进入共享制卡流程（见 `workflow-and-sync-rules.md`），额外注意：

### 来源标注

- 来自每日记录：参考来源写日期和对应的每日笔记链接
- 来自回顾记录：参考来源写回顾日期和对应笔记链接
- 来自 inbox 整理：参考来源写"inbox 整理"及日期
- 来自用户直接输入（无对应文件）：参考来源写"用户思考记录，{{日期}}"

### 来源笔记更新

- 如果来源笔记有明确路径（如每日笔记），在来源笔记中添加反向链接
- 如果来源是用户直接在对话中输入的内容，无需更新来源笔记

### 碎片合并

- 如果多条碎片记录指向同一个观点，合并为一张卡片
- 合并时保留各条碎片的不同角度，在"详细说明"中体现
