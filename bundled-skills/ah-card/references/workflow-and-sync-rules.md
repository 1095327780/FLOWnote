# 共享制卡与同步规则

本文件定义所有路径（收藏文章/文献笔记/用户笔记）共享的制卡步骤和同步规则。各路径完成前置阶段后，在制卡环节统一遵循本规则。

---

## 1) 深度充足性判定

每条候选在制卡前必须检查三项：

1. 观点是否明确（不是模糊话题）
2. 是否解释"为什么成立"
3. 是否提供边界/条件/场景（至少一项）

判定：

- >= 2 项满足 → 可制卡
- < 2 项满足 → 深度不足，先引导

## 2) 深度不足处理

当深度不足时，必须执行：

1. 告知不足点（具体到缺失维度）
2. 调用 `/ah-think` 进行深度引导
3. 收集用户补充后重新判定
4. 通过后继续制卡

示例提示：

`当前内容观点清楚，但缺少成立条件与适用边界。先用 /ah-think 做一轮深挖，再继续制卡。`

## 3) 制卡步骤

1. 标题：断言式完整句
2. 核心观点：一句话
3. 详细说明：完整保留为什么成立、具体实现、边界与适用条件，不以固定字数省略重要内容
4. 关联关系：保留所有重要且经原文验证的支持/反对/补充关系，不设条数上限、不凑数量
5. 用户确认：标题、正文、关联

## 4) 用户原话约束

- 标题和正文尽量使用用户原话
- AI 不得编造新观点或新例子补全卡片
- 若信息不够，写"待用户补充"，不自动补写

## 5) 关联发现（分层读取，禁止全量扫描）

按顺序执行：

1. 读取主题笔记标题（`{{notePaths.topicNotes}}/` 文件夹）
2. 读取领域页标题（`{{notePaths.domainPages}}/`）
3. 先选择与当前候选最相关的 1-3 个主题/领域，线索要求时继续扩展；首批不是关联上限
4. 读取这些主题笔记内容，提取其中现有链接笔记标题
5. 再读取候选笔记正文，确认能否建立关联
6. 输出建议关联并说明关系类型
7. 根据正文、别名、同义词和跨主题线索补充全范围本地搜索，继续未返回的候选游标。词法搜索不能证明隐含语义关系已全部找到；不得仅凭首批结果宣布全面检索完成。

禁止：

- 一开始遍历并读取所有永久笔记
- 未验证正文就直接建立关联

## 6) 保存与同步顺序（不可打乱）

1. 保存永久笔记至 `{{notePaths.permanentNotes}}/{{标题}}.md`
2. 更新主题笔记（在相关主题笔记中添加链接）
3. 更新来源笔记（具体方式因路径而异，见各路径的 guide 文件）
4. 更新反向链接
5. 输出汇总

### 来源笔记更新（按路径区分）

- **路径 A（收藏文章）**：若已存为文献笔记，按路径 B 处理；若未存，标注"收藏文章：《文章标题》"
- **路径 B（文献笔记）**：两处更新 — ① 「本书衍生的永久笔记」区块追加链接 ② 洞见条目的 `永久笔记:` 字段回填
- **路径 C（用户笔记）**：在来源笔记中添加反向链接（如有明确来源文件）

### 宿主建卡工具（可用时优先）

`card_prepare` 只打包确定性准备，不负责判断输入类型或关联。`sourcePath` 只使用用户明确指定的路径；已附加的原文可直接理解。标题目录超过首批时传 `catalogOffset` 继续。来源被截断时，用返回的 `vault_read` 参数继续，不能把宿主持有全文当作模型已经看过全文。

确认标题、正文和关联后，调用 `card_commit`：

- `card: {path, content}`：配置的永久笔记路径和用户已确认的完整正文；目标已有不同内容时停止，不能自动覆盖。
- `sync`：按 `topic`、`source`、`backlink` 顺序提供 `{path, role, old_string, new_string}`；所有旧片段必须在模型实际读到的范围内。`new_string` 包含新卡的完整路径 wikilink（省略 `.md`，可带显示名）。关联说明由用户确认，工具不自动推断。
- 文献来源的区块追加和洞见字段回填是同一 `source` 路径下的两条精确替换，不得只完成其中一处。没有真实来源文件或已确认关联时，明确说明原因，不能伪造同步目标。
- 每个目标可提供 `expected_fingerprint`；当前版本必须匹配。失败后重复相同计划可恢复，重启后的恢复还须重新读取当前目标并核对回执中的前后版本；不能用新版本掩盖旧计划冲突。
- 工具先校验全计划，再创建卡片和顺序同步，每个文件分别核验。多文件不构成原子事务；部分失败报告已验证、已尝试及未完成路径，从失败处恢复。仍需遵守现有写入权限。

若宿主没有提供该工具，使用原有 `vault_read` / `vault_write` / `vault_edit` 顺序完成相同义务；不因缺工具跳过来源或关联同步。

## 7) 失败恢复

若任一步骤失败：

1. 报告失败位置
2. 停止后续写入
3. 修复后从失败步骤继续

禁止静默失败。
